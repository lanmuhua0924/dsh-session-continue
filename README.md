# dsh-session-continue · 换窗接续

**一句话：换窗不是换人，可新窗一睁眼什么都没有。这个插件把上一窗的「摘要」和「最后几轮对话」塞给新窗，让它知道自己在哪儿、刚说到哪。**（另有可选的「交接页」，见下面。）

按工作区认「上一窗」，不跨工作区串味；只读盘、不写会话日志、不碰 dsh-memory；所有读盘写盘都有兜底，出错只记 `error.log`，不抛、不挡宿主。

## 它做什么

新会话第一轮起，自动往前插一段带 `[[sys-inject:session-continue]]` 前缀的文本，顺序是：

```
身份锚点（本窗 id ｜ 来源 id）
  → 换窗必读（可选）
  → 上一窗摘要（可选，读设置页里生成的那份）
  → 上一窗最后 N 轮对话
  → 交接页（可选）
```

预算按实际字数扣，不是死比例：总闸 `maxChars`（默认 20000），依次是「必读 → 摘要 → 交接页 → 最后对话”，每段各有单段上限，剩下的全给对话。截断按段落切，不切半句，段头写「还有 N 字没贴，完整版在这条路径」。

它**不**做这些：不写记忆、不碰 `dsh-memory`、不跨工作区、不在压缩时触发、不生成摘要（摘要由设置页单独生成，它只读那份文件）。

## 前提

- DeepSeek Harness（桌面版或命令行版都行），插件走 profile 里的本地目录链接。
- Node >= 22。

## 安装

放进 profile 的依赖里（本地目录链接，和 DSH 装本地插件一个路子）：

```jsonc
// <DSH_HOME>/profiles/<profile>/package.json
"dependencies": {
  "dsh-session-continue": "link:/你的路径/插件/dsh-session-continue"
}
```

再把它加进 bundle 选择列表，或者在 `<profile>/cordis.patch.yml` 里手加：

```yaml
- insert:
    - id: dsh-session-continue
      name: dsh-session-continue
```

重启 DSH 生效。

## 可选件：没有也能跑

> **先说一句**：下面出现的 `灵枢`，是作者自己工作区里的目录名，不是通用约定。你不喜欢就叫别的名字——要么按下一节把路径改成你自己的，要么干脆不建（这一整块都是可选的，缺了自动跳过，不报错）。

插件只在**约定路径**上找下面这些。**一个都没有，它照样工作**——只注入「最后 N 轮对话」，一句错都不报。想更完整，就照约定的位置放。

### 1) 上一窗摘要（推荐，最省事）

这是最像「人话」的一段：换窗前让模型把上一窗读一遍，写成五六段叙事——从哪儿接上、中间怎么走的、卡在哪、最后一句「这一窗的口气」。

- 怎么来：设置里打开「换窗接续」，点「生成上一窗摘要」。走宿主的模型流，不建会话、不留目录，一条命令的事。
- 落在哪：`<工作区>/灵枢/交接/窗摘要/窗摘要-<上一窗会话 id>.md`（这个路径是写死的；嫌名字别扭就改 `summaryDirFor`）。不想要 `灵枢` 这层？建软链接指过去，或者改那一处。
- 也可以不用它的生成：自己写一份同名 `.md` 放进那个目录，注入时一样读。
- 没有：跳过这一段（没配模型就是没有，其他照常）。

摘要写什么，有几条经验：写事不写报表（别按小时列表），原话引一两处就够，最后一定落一句「这一窗的口气」——下一个睁眼的人靠它知道自己是怎么睡着的。

### 2) 交接页（可选）

比摘要更「手写」的一种：上一窗临走前自己留的一张纸。

- 路径：**在工作区根目录建一个 `交接` 文件夹**，把 `.md` 放进去，例如 `<工作区>/交接/交接-20261121_1034.md`
- 取哪一个：按修改时间取最新一份；`README`、下划线开头的、`进度-` 开头的不认
- 没有：跳过这一段

想写的话建议这四块，别写台账：

```
这一窗干了什么 / 卡在哪、还欠什么 / 那几句原话 / 这一窗的口气
```

### 3) 换窗必读（可选）

- 路径：`<工作区>/灵枢/换窗必读.md`
- 作用：每次换窗自动带到最前面，写「人、钟、欠账」这类每次都要看的东西
- 没有：跳过（`autoBrief: false` 也能关掉）
- 不想建 `灵枢` 这个目录：不改代码它就是没有这一段；想要就把路径改掉，见下一节

### 想放在别的目录？

**路径是写死的**，两个办法，任选：

- 省事：在工作区里建上面说的目录（`交接`），或者用软链接指过去（Windows 上 `mklink /D`），插件不用改。
- 动代码：`lib/index.js` 里搜关键词改——`findHandoff`（`'灵枢', '交接'`；第二个候选就是 `cwd\交接`）、`briefPath`（`'灵枢', '换窗必读.md'`）。改完 `node --check lib/index.js` 过一遍。

## 配置项

存在 `<DSH_HOME>/storages/dsh-session-continue/config.json`，也可以直接在设置页改。

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `lastRounds` | `10` | 注入上一窗最后几轮；`0` = 不注入对话（别写成空，`0` 是有效值） |
| `maxChars` | `20000` | 注入总闸（按实际字数扣，见上面的顺序） |
| `minIdleMinutes` | `0` | 上一窗静置多久才算结束；默认靠「还活着的会话」排除，这个只防文件没落盘完 |
| `includeHandoff` | `true` | 要不要带交接页 |
| `autoBrief` | `true` | 要不要带换窗必读 |
| `autoReplantClocks` | `true` | 新窗要不要自动重挂定时任务（要你自己提供清单文件；没有就跳过，不报错） |
| `selectedSessions` | `{}` | 按工作区手动指定接续哪个旧窗：`{"<工作区路径>": "session-xxx"}`；不填就走自动选窗 |

## 设置页

DSH 设置里会多一节「换窗接续」。能改：接续轮数、注入总闸、静置分钟、三个开关；能按工作区挑「接续哪个旧窗」（含已归档的窗，标题上会标「已归档」）；还能一键「生成上一窗摘要」——走宿主模型流，不建会话、不留目录，落在 `<工作区>/灵枢/交接/窗摘要/`（这个落点也是写死的，嫌名字别扭就改 `summaryDirFor`）。

生成和注入是分开的：生成放换窗前做，注入只读文件，所以注入这边不卡。

## 工具

| 工具 | 干什么 |
|---|---|
| `session_continue_status` | 看开关、本窗状态、是不是重启恢复的旧会话 |
| `session_continue_build` | 只读重建一次，看这次会注入什么（不污染会话） |
| `session_continue_config` | 读/改上面那张配置表 |
| `session_continue_seat` | 换窗认领（`claim`）/ 看标记（`list`）/ 指定（`set`）；`.homeseat` 标记写在会话目录里 |

## 已知限制

- 「认领」写标记是破坏性动作，所以 `claim` 只认调用方自己的会话（`exec.agent.session`），拿不到就**直接拒绝**，绝不靠「活的会话列表最后一条」猜。单窗时稳；多窗同时活着时，用 `set` 明确传 id 最保险。
- 摘要生成要用宿主的模型流，没配模型就没有摘要，这时只有对话和交接页。
- 注入只做一次：内容进了上下文就不再重复，省 token。
